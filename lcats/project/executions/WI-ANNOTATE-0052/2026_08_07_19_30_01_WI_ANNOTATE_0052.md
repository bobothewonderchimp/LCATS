# Summary

Implemented WI-ANNOTATE-0052: extended `lcats promote`'s
`survey_collection` release gate to validate `genre.json`/`scenes.json`
sidecar content, so a malformed sidecar blocks promotion instead of
being silently wholesale-copied to `corpora/`.

# Result

- `promote.py`: added `MalformedSidecarFinding` dataclass (parallel to
  `BlockingFinding`), a `CollectionSurveyResult.sidecar_findings` field,
  and `_validate_sidecars()` — checks each story bucket's
  `genre.json`/`scenes.json` (when present) for valid JSON, top-level
  dict shape, and the one required key each sidecar's real writer
  (`annotate.py`) always populates (`detected_genre`/`segments`).
  `clean` now requires zero sidecar findings alongside the existing
  mojibake/story-count checks.
- `promote_cli.py`: surfaces `sidecar_findings` in the `blocked:`
  reporting, not just mojibake findings.
- `annotate.py`: added `GENRE_SIDECAR_FILENAME`/`SCENES_SIDECAR_FILENAME`
  named constants (was 6 inline string-literal occurrences), used
  consistently in both modules to avoid the filename convention
  silently drifting apart.
- 7 new tests in `promote_test.py`: valid genre-only, valid scenes-only,
  malformed JSON, wrong top-level type, missing required key,
  no-sidecars-unaffected (today's normal case), and an end-to-end
  `promote_collections` block-not-copied case.
- Verified no circular import: `annotate.py` doesn't import `promote.py`.
- Fixed the editable-install-pointing-at-a-different-worktree issue
  twice more this session (recurred from concurrent sessions' own
  `scripts/develop` runs) — verified `module.__file__` before trusting
  each test run.

  diff + WI orientation) — no findings; independently spot-checked its
