# Result

- `src/lcats/analysis/corpus/annotate.py`: core logic.
  `annotate_collections` enumerates collection directories under
  `--source` first (mirroring `promote.promote_collections`), then
  `annotate_collection` calls `discovery.iter_collection_story_files`
  once per collection — confirmed via a real dry-run smoke test against
  `corpora/` that this correctly processes every collection when given
  a multi-collection root, not just a single named collection (PR #226
  review finding this design deliberately avoids).
- Checkpoint bookkeeping (via `lcats.utils.checkpoint`) lives in a
  dedicated `--checkpoint-dir` (default `.annotate_checkpoints/`),
  confirmed via a user decision during plan confirmation: never
  `data/`/`corpora/`/`cache/`, since `checkpoint.resolve_roots` refuses
  a working_root under the protected data/corpora roots and both are
  disposable/wiped by `lcats clean`. The real `genre.json`/`scenes.json`
  sidecars are written by `annotate.py`'s own code directly into each
  story's bucket in `data/`, separate from checkpoint's own wrapped
  bookkeeping file.
- Fingerprint = model + system-prompt hash + tool-schema hash +
  story-body hash (tool-schema hash added during self-review, see
  below), so a checkpoint invalidates on any of: model change,
  prompt/schema change, or a corrected story — verified via
  `PROP-LCATS-PIPELINE-CHECKPOINTING`'s own Decision 2 text.
- `annotate_cli.py`: `build_parser()`/`run()`, mirroring
  `promote_cli.py`'s shape.
- `cli.py`: registered `annotate` following the exact `assess`/`promote`
  pattern.
